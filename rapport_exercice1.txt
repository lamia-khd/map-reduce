1. OBJECTIF & IMPLEMENTATION (PaymentJob.java)
- Mapper (PaymentMapper) : Valide 6 colonnes (sinon QUALITY.MALFORMED_LINES++). Emet (payment, 1).
- Reducer / Combiner (SumReducer) : Somme les occurrences par mode de paiement.
- Validite du Combiner : L'addition est associative et commutative (a + b = b + a),
  donc pre-agreger localement ne change pas la somme finale.

2. REPONSES AUX QUESTIONS

Q1. Sortie attendue sur mini.txt (10 valides, 2 malformees) :
Amex        1
Cash        2
Discover    2
MasterCard  2
Visa        3

Q2. Types cle/valeur :
- Intermediaires (Mapper/Combiner) : Cle = Text (payment), Valeur = IntWritable (1 ou sous-total)
- Finales (Reducer)                : Cle = Text (payment), Valeur = IntWritable (total)

Q3. Taches Map sur purchases.txt :
- 2 taches map lancees.
- purchases.txt fait ~201.5 Mo. La taille de bloc HDFS est de 128 Mo.
  Le fichier necessite donc ceil(201.5 / 128) = 2 blocs = 2 InputSplits = 2 Maps.

Q4. Modification pour 3 Reducers (job.setNumReduceTasks(3)) :
- Nombre de fichiers : 3 fichiers (part-r-00000, part-r-00001, part-r-00002).
- Repartition HashPartitioner : partition = (key.hashCode() & Integer.MAX_VALUE) % 3
  * Partition 0 (part-r-00000) : Amex (1), Cash (2), Discover (2)
  * Partition 1 (part-r-00001) : (vide)
  * Partition 2 (part-r-00002) : MasterCard (2), Visa (3)

3. COMPTEURS YARN (Impact du Combiner sur purchases.txt)
- Sans Combiner : 4 138 476 records transferes via shuffle (~45.5 Mo).
- Avec Combiner : 10 records transferes (142 octets) -> Reduction de 99.99% du trafic reseau.
